    手动上下文压缩 /compact

    自动压缩在请求超过预算时触发。一个阶段结束后，也可以主动整理旧资料，再继续工作。本章增加本地命令 /compact，复用已有的摘要校验与工具消息分组。

    使用方法

    /compact
/compact 重点保留任务编号、禁止修改测试的约束和未完成事项
/save compacted

    关注点可省略，最多 1000 字符；多个词按空格连接，含引号时遵循命令行 shlex 规则。它只影响摘要强调的信息，不授权执行工具，也不能提高权限。计划模式和启动只读权限下均可压缩。

    手动压缩成功后显示请求字符数变化与完整备份路径。字符数包含工具定义，不是 token 数。恢复备份时用文件名去掉 .json 的名称：

    /load manual-<编号>

    这会恢复原始消息并进入计划模式，不撤销文件、不重放工具。若要继续修改，仍需本地 /execute 和原有操作确认。

    执行流程

    1. 取得工作区执行锁，校验历史消息协议。
    2. 先保存 .fast-agent/sessions/manual-<编号>.json 原始备份。
    3. 根据 keep_rounds 保留最近轮次；必要时只摘要较早的完整工具批次，保留最近批次及当前用户目标。
    4. 调用摘要模型，工具列表为空。关注点作为明确标注的摘要偏好加入提示。
    5. 校验摘要非空、长度、无工具请求、消息配对完整，且请求字符数实际减少。
    6. 全部通过后才替换内存历史；显式 /save 保存压缩后的会话。

    原始历史未达到自动压缩阈值时也会处理。--context-chars 0 仅关闭自动触发：手动压缩仍可用，此时以原请求大小作为压缩结果上限。配置了非零预算时，结果还必须满足该预算。

    空会话或没有足够较早完整消息时，不调用模型并提示无法安全压缩。非空但不能压缩的历史可能已经生成备份；不会为了缩短内容拆开工具调用和工具结果。

    失败时发生什么

    备份写入失败时不调用模型。模型失败、返回工具调用、摘要过长、摘要未缩小上下文或用户中断时，原历史不变。已保存的备份保留，失败消息包含其路径。该命令不更新旧任务检查点；/resume 恢复原检查点，需要恢复压缩结果时使用 /save 与 /load。

    模型摘要仍可能遗漏或误述事实，格式检查不能证明语义完全正确。关键约束应核对摘要或备份；继续修改前重新读取当前文件。关注点不会被当作新的工程操作指令。

    真实 MiniMax 验证

    source .env
.venv/bin/python examples/real_manual_compaction_demo.py

    第一个进程让 MiniMax 读取资料、源码和测试，给出计划，再通过 /compact 主动摘要、核对原始备份并保存压缩会话。第二个进程加载会话，确认仍为计划模式，再由宿主显式切换执行，让模型复现失败、修复、重跑测试并核对 Git 差异。

    任务编号只在初始任务中给出；恢复后的提示不重复编号。验收同时检查摘要保留编号和测试限制、模型继续任务时引用编号、测试文件不变、只修改目标源码。

    报告保存在 .fast-agent/validation/manual-compaction-demo.json。
