FAST AGENT / 工作区与子 Agent

并发只读委派

同步委派依次探索多个问题；并发委派允许不同客户端同时读取同一工作区。它不赋予子任务修改权限，也不把子报告直接变成主会话指令。

/delegate-parallel ["读取项目入口并说明职责", "查找测试目录并列出覆盖范围"]

每批最多 5 个任务，默认 2 个并发工作者，内部接口最多 3 个。每个任务只拿到内置只读工具、独立历史与独立 HTTP 客户端，不能继承本地扩展对工具的覆盖。所有客户端共享同一个加锁的 UsageTracker，请求预算不会按子任务重置。报告按输入顺序返回，但实际完成顺序可能不同。

每个报告仍有独立 ID，可以用 /delegation ID 读取，再用 /delegation-summary ID… 显式汇集。报告 completed=true 只表示执行循环完成，结论仍需主任务核验。

取消与失败

运行期间 Ctrl+C 设置批次取消信号。下一次模型请求前检查信号；正在发送的请求返回后再检查，不执行其返回工具。取消产生未完成报告，不声称远端请求已经强制停止。等待时间受模型读取超时及有限重试影响。客户端在子任务结束时关闭。

客户端创建或执行异常写入脱敏的未完成报告；报告无法落盘时仍向入口报错，不能伪称证据保存成功。执行线程仅在进程内；持久批次恢复规则见下文。自定义模型必须实现独立客户端工厂，否则拒绝并发调用。

本地测试验证实际并发重叠、客户端关闭、独立报告、取消前无请求与失败脱敏；MiniMax 并发验收 8/8 项通过：两任务实际读取、独立报告、共享预算、主历史与源文件不变、批次核实完成；4 次请求，5773 已报告 token，unknown_requests=0。

批次持久记录与恢复

批次在发请求之前写入 delegation-batches：任务与预分配报告 ID 一一对应。/delegation-batches 列出 ID，/delegation-batch-reconcile ID 在活动锁释放后只核实引用报告；报告缺失、损坏或任务不匹配标记为 missing_or_invalid，不会自动重跑。正常完成同样核实每份报告，任一未完成则整批为 incomplete。

工作区移动会拒绝 running 批次；执行期间同时持有工作区任务锁。进程强制退出留下的 running 记录需先核实。核实为 incomplete 仅表示不再运行，不表示任务成功；报告和批次证据仍保留。

取消边界还有独立反例测试：模型返回工具调用的同时设置取消信号，注册表执行入口被测试替换为“一旦调用就失败”。结果必须是不执行该工具、关闭客户端，并保存 completed=false 的报告。这样验证的是副作用确实被阻断，而不只是最终文字出现“已取消”。
