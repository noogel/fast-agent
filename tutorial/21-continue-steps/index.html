FAST AGENT / 任务执行与权限

任务继续执行与步数控制

达到调用上限不等于任务失败，也不代表目标已经完成。本章让暂停原因、继续入口和恢复方式在终端中清楚可见。

常用命令

/steps
/steps 15
/continue
/continue 请先核对测试结果，再处理剩余问题

/steps 查看当前上限，带整数时调整后续每轮模型调用次数，范围 1～1000。启动参数 --max-steps 使用相同范围，默认 10。设置只保存在当前进程，加载会话不会从文件继承该配置。

/continue 是显式发起模型调用的本地入口：附加一条继续任务的用户消息，携带当前历史进入现有 Agent 循环。补充说明可省略，最多 4000 字符。空会话无法继续，应先输入任务或加载历史。已完成的任务也可以用它发起后续检查，它不是“仅未完成任务”状态机。

达到上限时

Agent 完成当前模型回复中的工具批次，再检查是否还有下一次模型调用预算。达到上限时，返回未完成状态，保留工具结果，并保存 incomplete 检查点。终端提示 /steps、/continue 以及启用检查点时的任务编号。

一个模型回复可以包含多个工具调用，所以步数限制不是工具数量限制，也不是总耗时或费用上限；自动压缩的摘要请求和网络重试不计入这个循环步数。

fast-agent --workspace /path/to/repo --resume <检查点编号>

恢复后先处于计划模式。需要修改时显式切换：

/steps 15
/execute
/continue 请继续修复并实际运行测试

也可以 /save 名称，下一进程通过 --load 名称 恢复。每次继续复用 run()，启用检查点时创建新的任务编号，旧检查点保留。

不重放意味着什么

宿主程序不会遍历历史重新执行旧工具调用。模型会看到已有结果和继续说明，然后生成新的决策；它仍可能主动提出再次读取或测试。继续提示要求先核对已完成事项，但这不是对所有副作用的去重保证。

计划模式保持只读，启动 read-only 权限不能被 /continue 或 /steps 提升。结果未知的旧操作仍由任务记录阻止写入，需要先人工核实；增加步数不能绕过这些检查。

最后一步若只完成工具调用，还没有模型最终总结，整轮仍属于未完成。继续后模型可以依据已有工具结果总结，无需自动重跑它们。

MiniMax 验证

source .env
FAST_AGENT_READ_TIMEOUT=120 FAST_AGENT_MAX_RETRIES=1 \
  .venv/bin/python examples/real_continue_steps_demo.py

首进程设置 1 步，要求 MiniMax 先读取源码和测试。产生工具结果后达到上限，检查 incomplete 状态及恢复提示并保存会话。

第二进程调用 CLI --load planned --max-steps 1，核对计划模式，再输入 /steps 15、/execute 和 /continue。模型实际复现失败、批量修复两个函数、重跑测试并检查 Git 差异。宿主核对测试未改、只修改目标源码、获批操作都在指定范围内。

报告写入 .fast-agent/validation/continue-steps-demo.json。单元测试另外核对旧工具结果保留、不会由宿主重放、恢复后的权限边界及非法步数。
