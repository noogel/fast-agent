    04 · 对话变长后怎么办

    你昨天让 Agent 读了 math_utils.py，保存会话后退出。今天文件被同事改过，你恢复会话，模型却还记得旧代码。这算“有记忆”还是“记错了”？

    答案取决于你说的是哪一种状态。

    把三种状态分开

    状态 修复测试时的例子 保存对话能否保证它仍然有效
    模型可见消息 用户目标、旧文件正文、上次测试输出 只能保留当时的信息
    宿主程序状态 当前权限、读取版本标记、工具注册表 不能把旧授权直接视为当前授权
    外部真实状态 磁盘文件、Git 差异、正在运行的命令 必须重新检查

    Fast Agent 每轮向模型提供历史消息和工具定义。模型不会因为本地目录存在某个文件，就自动看见文件内容；需要工具读取并把结果放进消息。同样，程序里的权限对象也不会天然成为模型的记忆。

    保存、裁剪和压缩不是一回事

    操作 对消息做什么 主要取舍
    保存与加载 把历史落盘，之后读回 保留消息不能更新外部事实
    裁剪 移除较旧的对话轮次 简单，但被删信息不再直接可见
    压缩 用摘要替代部分旧信息 节省空间，但摘要可能遗漏或失真

    先决定要解决的是“退出后接着聊”，还是“当前请求太长”，再选择操作。不要为了保存会话而先压缩，也不要把裁剪当成无损保存。

    压缩为什么可能改变后续判断

    长对话中，几十轮命令输出会挤占请求空间。压缩用较短摘要替代旧信息，但摘要是有损的：目标和主要结论可能保留，某条错误日志的细节可能消失。

    例如原始记录说“测试 A 通过，测试 B 因依赖缺失未运行”，不准确的摘要若写成“测试通过”，就会误导交付判断。重要测试证据应保存在独立记录中，需要时重新读取或复测，不能只依赖摘要里的结论。

    Fast Agent 的压缩逻辑会维护工具请求与结果的配对关系；手动压缩先备份历史，成功后才替换内存中的对话。当前字符预算只是占用估算，不等于模型实际 token 窗口，也不代表已实现服务端超限自动恢复。

    代码入口：compaction.py。操作见手动压缩。

    什么时候该读全文，什么时候只取片段

    为了定位加法错误，你可能只需要函数和关联测试。先检索再分段读，通常比一次读取整个仓库更容易保留相关信息。但只读命中行也可能漏掉调用约束，因此需要再补周边代码。

    这是一种取舍：少读会丢上下文，多读会淹没关键证据。工具结果有界输出和长日志按需读取，让模型先看到定位信息，再按需要取回正文。落盘引用不是永久记忆：它仍依赖相应文件可读，引用保护、隔离与恢复策略见存储回收，不能把已回收内容当作仍可读取。

    动手核对

    先用 /save 保存一个短会话，使用 /history 查看原始记录。再对有足够历史的会话执行 /compact，比较压缩前后的目标、约束和失败信息是否保留。命令参数详见会话教程和手动压缩；压缩会请求模型。

    自测

    问题：保存会话后删除工作目录，再加载会话，能否恢复代码文件？

    答案：不能。会话消息是历史知识，不是整个工作区备份。代码恢复、任务恢复和对话恢复需要不同的机制。
