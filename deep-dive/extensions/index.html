07 · 怎样扩展和分工

当加法修复流程跑通后，你想把它用于更多项目。新需求可能是“增加一种操作”，也可能只是“记住这个项目的工作方法”。先分清需求，再选择扩展机制。

四种机制对应四种问题

需求 机制 在 Fast Agent 中的含义
需要一种新的可执行操作 Tool 注册参数约定和处理函数，沿用权限检查
每次都要重复讲项目操作步骤 Skill 按需读取 SKILL.md 与配套资源，提供工作方法
需要调用另一个服务的能力 MCP 通过协议发现并调用服务提供的工具
希望独立分析一个子问题 子 Agent 创建独立对话，受限执行后返回报告

Skill 中写了“运行测试”不等于测试已经执行。MCP 提供了工具接口，也不意味着远端服务天然可信。子 Agent 得出的结论仍需核实。这些机制都不能替代用户授权。

用同一个任务选择机制

如果团队测试有固定准备步骤，可以写成 Skill，让 Agent 按需读取。如果需要查询远端构建服务，可以接入 MCP 工具。如果只是想独立分析测试覆盖，可以显式委派一个只读子任务。

不必为每一个辅助函数创建子 Agent。独立对话有信息隔离的好处，也增加请求开销和报告交接成本。Fast Agent 支持单次只读委派和有界并发只读委派；并发任务使用独立历史与客户端，但共享请求预算。它们仍不能编辑工作区。

材料、连接与任务各有自己的生命周期

扩展能调用一次，只解决了第一步。长期运行还要回答三个具体问题：

情况 应如何处理 实践
读过 Skill 后，配套规则或脚本发生变化 重新检查资源树版本，失效旧的读取标记，再读取材料 Skill 整体资源树
MCP 服务更新工具，或访问令牌过期 显式刷新工具定义；使用 OAuth 时由控制层处理令牌，不把凭据交给模型 连接生命周期、OAuth
同时启动两个分析任务，中途退出 保存任务与报告 ID；恢复时核实已有报告，缺失报告不自动重跑 并发只读委派

例如两个子任务分别检查入口和测试，可以并发读取；如果其中一个失败，另一个成功不会让整批自动成为成功。取消也只阻止后续请求和工具执行，正在等待的模型请求仍需返回或超时。读取报告时要同时看结论、来源和完成状态。

报告怎样回到主任务

主任务：修复加法错误
子任务：只读检查关联测试覆盖
结果：独立报告及来源 ID
本地汇集：/delegation-summary ID
主任务后续：核实报告，再决定操作

当前汇集命令不会自动向父历史注入内容，也不请求模型解决报告分歧。它只把指定报告按来源整理出来。把这一限制写清楚，比把“多 Agent”当作自动增强可靠性的保证更有用。

动手核对

在临时仓库运行 /delegate 只读检查加法函数有哪些测试，再用 /delegations 和 /delegation ID 查看结果。检查父历史是否保持独立，以及报告中是否保留工具失败或未完成状态。真实模型运行需要已有配置，仍消耗共享请求预算。

操作入口：Skill、MCP、只读委派。源码：skills.py、mcp_tools.py、delegation.py。

自测：Skill 和 Tool 都能描述“运行测试”，区别是什么？ Skill 提供方法与材料；Tool 提供实际执行接口，调用仍需通过宿主检查。
