# MCP OAuth 生命周期实现与验收

依据 [MCP 2025-11-25 Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)，HTTP 授权必须绑定资源，发现授权服务，使用 PKCE，并保护回调与令牌。stdio 继续沿用环境凭据。

实施顺序：

1. 授权事务：S256、随机 state、5 分钟有效期、精确回调地址、一次性授权码消费、resource 绑定。（当前已实现纯协议组件，未接网络或 CLI。）
2. 资源元数据和授权服务发现：支持 challenge 与 well-known、OAuth/OIDC；issuer/端点校验、无凭据 GET、不自动跟随重定向、显示新授权域供用户明确批准。
3. 预注册公共客户端登录：绑定回环监听器再生成授权 URL；浏览器由用户完成授权；交换授权码且不自动重试，以免重放。后续按支持情况扩展客户端元数据机制，不伪称已实现全部注册方式。
4. 私有凭据仓储：与工作区运行日志隔离，不进会话/模型上下文/报告；令牌类型/过期/资源及授权方绑定检查。刷新旋转原子保存、并发锁、失败后需要重新登录；不能把未知刷新结果当成功。
5. HTTP 工具接入：请求前选择目标资源凭据，不跨资源复用、不携带令牌跟随重定向；状态仅显示脱敏元数据。登出删除本地凭据，远端撤销只在支持时明确执行并区分结果。

验收包含本地协议与 HTTP 授权服务夹具、过期刷新/旋转/撤销/错误/敏感信息不出现在日志、真实 MCP 工具调用。外部服务需要用户实际授权时再进入授权交互；本地夹具不是外部真实用户授权证据。
