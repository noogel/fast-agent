# 06 · 中断后怎样继续

Agent 已经发起“修改文件并运行测试”，终端突然退出。重新打开后，你只看到上一次的工具请求，没有看到结果。能不能直接再执行一遍？

## 没收到结果，不等于没有执行

至少有三种可能：请求还没开始；文件已经修改但测试未结束；测试也结束了，只是结果没保存。它们在对话里可能表现得很相似，磁盘上的事实却不同。

读取文件通常可以安全重试。写文件、启动后台任务或执行外部命令则未必如此。重复执行可能覆盖新修改，或启动第二个相同进程。恢复的第一步应是核对实际状态，而不是把旧请求全部重放。

## 对话、任务与工作区是不同的恢复单位

| 机制 | 能帮助恢复什么 | 仍需核对什么 |
| --- | --- | --- |
| 会话保存加载 | 目标与历史消息 | 当前文件和权限 |
| 任务检查点 | 待执行、活动操作与任务状态 | 中断时副作用是否完成 |
| worktree 归档恢复 | 独立工作目录和其中的证据 | 活动任务、移动状态和路径归属 |

在启用检查点时，Fast Agent 把执行状态保存在任务记录里；存在不确定操作时，需要核实并解除阻塞。它不提供所有外部系统上的“恰好执行一次”保证。查看 [tasks.py](../reference/src/fast_agent/tasks.py.md) 和 [Agent.resume](../reference/src/fast_agent/agent.py.md)。

## 用证据决定继续哪一步

假设当前源码已经是 `a + b`，但没有可靠的测试结果。先读取文件和 Git 差异，确认没有额外修改，再执行适用测试。若测试通过，就无需重复编辑。

如果任务记录显示操作状态未知，先调查实际副作用，再使用项目提供的核实流程。不能仅为了继续运行就把未知状态标成成功。worktree 的归档与恢复属于另一种恢复单位，具体操作见[安全归档](../tutorial/41-worktree-archive.md)。

## 保存记录后，也要考虑何时能删除

恢复依赖证据。把旧报告删掉后，会话中即使还保存着报告 ID，也无法重新读取原始结果。因此，回收首先检查引用，再检查保留期；“文件很旧”本身不是删除依据。

Fast Agent 分三步处理：[预览、隔离与永久回收](../tutorial/46-storage-retention.md)。预览只列出候选；隔离保留原始字节，可以恢复；永久回收要求隔离保留期已满、重新核对引用并再次确认。确认期间出现新的引用，也会阻止删除。worktree 清理证据包与 Git 保护引用目前不属于该接口的回收候选。

同样，保存一条用户答复不等于保存永久授权。[持久提问](../tutorial/45-durable-questions.md)恢复的是问题与回答关联；执行模式和危险操作仍须经过当前权限检查。

## 动手核对

先在临时目录练习保存并加载会话，观察恢复后切回计划模式。进一步阅读[任务与后台命令](../tutorial/10-tasks-jobs-permissions.md)，在可丢弃任务中核对待执行、活动和完成记录的区别。不要用有外部副作用的命令练习中断。

## 自测

**问题：恢复后发现源码已改、测试结果缺失，应该直接再次编辑吗？**

答案：先读取当前源码和差异，确认修改是否已经符合目标，再运行适用测试。只有发现新的证据要求修改时才继续编辑。记录中缺少结果，应当触发核实。
