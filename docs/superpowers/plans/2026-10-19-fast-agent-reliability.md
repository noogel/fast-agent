# Fast Agent：任务可靠性与后台命令

用户已在当前会话确认连续实现：任务检查点与恢复、后台命令、权限策略，并用 MiniMax 完整验证。沿用当前分支顺序开发，不创建独立实现任务。

## 实现顺序与验收

1. 权限：只读、默认确认、用户显式指定精确 argv 白名单；模型不能提升权限。文件编辑继续展示差异并检测外部变化。
2. 检查点：工具执行前后原子保存；恢复消息而不重放；未知副作用阻止后续修改，只有本地人工核实命令可以解除。跨进程锁防止多个主循环同时写入。
3. 后台命令：独立执行器、持久 ID、有界日志、超时与协作取消；执行器失联标记未知并阻止修改，不以历史 PID 直接杀进程。
4. CLI 和中文教程：任务恢复、日志查询、取消、核实及策略参数。
5. 自动测试覆盖进程直接退出、已完成结果恢复、未知结果、权限拒绝、后台跨进程存活、输出限额、超时和提前取消。真实模型在临时目录完成编辑、后台测试、三进程中断恢复和取消。

## 实施中确定的边界

- CLI 默认保存检查点，Python API 通过 checkpoints=True 启用。
- 保留现有同步命令；新增后台工具，不隐式改变旧命令语义。
- 不承诺恰好一次执行，不自动重放历史调用。已完成结果保留；模型之后仍可能提出新的重复操作，权限控制仍生效。
- `ToolInputError` 只用于明确的副作用前校验；其他修改类 handler 异常保守标为未知。
- 后台任务最长一小时；无系统沙箱、远程调度或机器重启后的自动重启。
- `.fast-agent` 和 `.git` 不能通过文件编辑工具修改；获准命令并非沙箱。
- 审查发现的副作用后异常、失联任务和排队取消问题均加入回归用例；前置路径拒绝不应误判为未知副作用。
