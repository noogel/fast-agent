# 先看引用，再决定回收

长时间使用后，工具大结果、委派报告和问题记录会逐渐积累。旧文件不一定没用了：保存的会话可能还持有它的 ID。

```text
/storage-preview 30
```

命令只做预览，不删除文件。候选范围是问题、委派和工具大结果的 JSON 记录；默认保留 30 天，按文件修改时间估算。输出包括候选、受保护记录、引用来源和阻塞项。

出现以下情况时保留：未满保留期；问题未回答；其他运行记录包含该 ID。活动或未知状态会阻塞回收。存在损坏记录、链接、扫描超限时直接报错，不能把没读到的引用当作不存在。

当前引用识别采用保守的 ID 文本匹配，可能多保留，不是语义引用图。扫描包含主工作区以及 worktrees、archived-worktrees、restored-evidence 下独立工作区的 `.fast-agent` 记录；全局最多 32 个工作区、1000 条记录、32 MiB。隔离 `.record` 和清理证据包中的快照内容也参与引用匹配。子工作区记录只作为引用依据，不成为主工作区回收候选。清理证据包、Git 保护引用和工作区本身不在自动候选范围。

可恢复隔离与恢复已接入下方命令，永久回收需按下方保留期和确认流程执行，不应手工按候选列表直接删除。实现入口：[retention.py](../../src/fast_agent/retention.py)。

## 从预览到可恢复隔离

使用 `/storage-preview 30` 查看候选和 fingerprint 后，执行 `/storage-quarantine 指纹 30`。这一步需要现有权限控制的确认：再次扫描全部记录、比对引用和内容指纹，变化则拒绝。确认前应停止其他写入运行记录的进程；任务锁只能约束遵守本项目锁协议的进程，不能冻结外部编辑器。

候选通过独占创建硬链接、核对哈希与文件身份，再移除原名字的方式移入私有隔离目录，原始字节保留；目标已存在则拒绝。读取哈希时不跟随符号链接，并拒绝特殊文件。返回批次 ID 后可用 `/storage-restore ID` 恢复原路径。恢复拒绝内容变化、缺失和已有目标冲突，绝不覆盖冲突文件。崩溃后可对部分移动/恢复状态重新恢复；如果同一记录两个位置同时存在，则保守报错，保留两份供人工核实。移动/恢复中状态也会阻止工作区归档。

这只是可恢复隔离，不释放全部磁盘空间。永久清除仅适用于下方已到保留期的隔离记录；worktree 清理证据包和 Git 保护引用仍不属于回收候选。

## 永久回收隔离记录

```text
/storage-purge-preview 批次ID 30
/storage-purge 批次ID 预览指纹 30
```

隔离保留期默认 30 天，最短 7 天。以成功隔离时记录的时间为准，不使用隔离文件的 mtime。旧版本缺少时间记录的批次不能直接永久删除，需先恢复再隔离。

预览重新检查当前及独立工作区引用、内容哈希、活动状态与原路径冲突。仅忽略本批次清单和本批次待一起删除的隔离内容；其他批次、会话、归档工作区或清理快照中的引用都会拒绝删除。执行还需不可逆确认，并再次扫描。计划模式与非交互无授权时拒绝。

每项在删除前保存 `deleting` 意图，删除后保存 `deleted`，全部完成后标记 `purged`。中断时可以重新预览同一批次；只有已有删除意图的缺失文件才能被接受，仍需再次确认才继续，不会后台自动重放删除。清单、哈希和时间记录保留，内容永久删除后不能再恢复。工作区、清理证据包、Git 保护引用不在此接口的删除范围。

运行回收期间应停止外部写入进程；内部任务锁不能冻结其他程序。测试使用临时目录，覆盖保留期、引用保护、确认期间新增引用、删除中断及再次授权。

## 清理证据与 Git 保护引用保留多久

普通内容和恢复证据使用不同保留规则。预览输出中的 `retention_policy` 明确列出以下三类记录，`automatic_expiry: null` 表示没有自动到期时间：

| 对象 | 保留原因 | 普通回收行为 |
| --- | --- | --- |
| `worktree-cleanups` 证据包 | 保存被清理工作区的文件快照与任务证据 | 不隔离、不永久删除 |
| `refs/fast-agent/cleanups/…` Git 引用 | 防止被清理工作区所指提交被 Git 垃圾回收 | 不修改、不删除 |
| `retention` 审计清单 | 永久删除后仍能核对原路径、哈希、时间与状态 | 始终保留清单 |

`retained_evidence` 列出扫描到的证据包和回收清单的路径、字节数及哈希，便于核对空间来源。该列表不是恢复成功证明；它也没有检查 Git 引用是否实际存在。验证具体工作区时仍需使用清理核实/恢复接口，它们会核对受保护提交。

这意味着永久回收普通工具结果后，证据包仍可能占用空间。这是明确的保留策略，而不是后台遗漏清理。当前不提供删除唯一恢复证据或 Git 保护引用的命令；不能为了腾空间手工删除它们，然后仍宣称可恢复。备份或迁移主仓库时，应一起保存 `.fast-agent` 记录和这些本地 Git 引用。

## 完整流程验收

已有真实模型配置后，可运行：

```sh
python examples/real_retention_demo.py
```

脚本只操作自己创建的临时工作区。模型先实际分页读取长工具结果，宿主保存含该 ID 的会话，检查结果受到引用保护。移除该临时会话后，宿主走预览、确认隔离和恢复，逐字节核对原记录，并再次通过读取工具访问它。

另一份无引用结果用于验证永久清理：保留期未满必须拒绝，夹具模拟时间过去后才允许清理，删除后审计清单仍存在，前一份恢复证据不受影响。时间推进只属于测试夹具，真实使用时不要修改时间记录绕过保留期。模型负责读取验收；隔离与删除由本地控制层执行，不把删除授权交给模型。
