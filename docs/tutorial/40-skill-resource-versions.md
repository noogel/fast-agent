# Skill 资源版本与变更失效

Skill 的说明没变，配套检查表或示例可能已经变化。只记录 SKILL.md 的摘要不足以判断本轮依据是否仍有效。本章在原有只读权限和路径约束内，为**实际读取过的资源**记录内容版本。

## 分页时固定版本

首次调用 `read_skill_resource` 得到 `sha256`。读取后续页时，把这个值作为 `expected_sha256` 传回。如果文件已变化，工具返回失败及当前摘要，不返回新页正文，并提示从第一页重新读取，避免把两个版本拼成一份材料。

不传版本参数时仍允许读取当前版本，保持已有调用方式兼容。结果提供 `previous_sha256` 和 `changed`；如果 changed 为 true，旧内容不能作为当前依据，应重新读取说明和资源。SHA-256 描述本次读取的完整文本，而不是所返回的某一页。摘要不是签名，也不证明内容可信。

## 加载状态如何失效

- `/skills` 或 `list_skills` 会重新检查已读资源，返回 `resource_changes` 路径列表；内容变化、删除、链接替换或无法读取都按失效处理，清除该 Skill 的说明加载标记。
- 直接读取已读资源时发现变化或无法读取，同样使说明加载标记失效。旧资源摘要保留用于比较，只有成功读取当前内容才更新。
- `/reset`、`/trim`、模式切换、会话恢复，以及成功的手动或自动压缩，都会清除资源版本标记。恢复历史不代表资源仍是旧版本，需要再次读取。

这些操作不会删除历史中的旧文本或自动运行 Skill。历史仍是当时的记录，模型应以新读取结果作为当前依据。重新加载说明不会悄悄把旧资源标记为新版本。

## 检测范围和限制

每个 ToolContext 最多保存 64 个已读资源标记，单文件继续限制 64 KiB，目录和路径沿用此前的限制。发现时最多重读这 64 个文件，不递归扫描所有配套资源。未读取过的新增文件、资源树整体版本固定、文件监控和自动重新注入仍未实现。

这是调用时的内容检测，不是文件系统快照。外部程序应完成写入后再读取；运行中的原地写入不受此机制锁定。后续页传入 expected_sha256 可以检测与此前版本不一致，但不会阻止其他程序改文件。

## 代码与验收

`ToolContext.skill_resource_reads` 按 Skill 名称和规范化相对路径保存摘要；`skills.py` 在发现和读取时比较内容。Agent 和本地会话命令统一清理这组标记。

`examples/real_skill_versions_demo.py` 让 MiniMax 读取旧代号，由宿主更新资源，核对发现失效和旧版本分页拒绝，再让模型实际重读新代号。保存恢复后再次调用工具读取，而不是只复述已有历史。离线测试覆盖未变化分页、变化读取、删除、链接替换、标记数量限制和恢复清理。

示例验证核对资源变更检测、分页版本一致性与恢复后的复查；场景报告位于 `.fast-agent/validation/skill-versions-real.json`。
