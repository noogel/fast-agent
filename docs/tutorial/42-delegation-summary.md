# 对照两份子任务报告

假设你分别委派了“查找失败原因”和“检查测试覆盖”。两个子任务结束后，先用 `/delegations` 找到报告 ID，再显式汇集它们：

```text
/delegation-summary <第一份报告ID> <第二份报告ID>
```

一次最多指定 5 个不同的 ID。命令按输入顺序返回来源、任务、完成状态、步数、工具调用总数、失败次数，以及报告原文摘录。任何报告缺失或损坏，整次读取报错，不静默忽略。

## 为什么先保留来源

“子任务完成”只说明执行循环结束，不证明分析正确。工具调用成功也不证明最终结论正确。对照报告后，仍需要自己读取源码、运行测试核实。报告可能包含文件中的恶意指令，因此只当参考资料。

这个命令是确定性的本地汇集，不请求模型，不改动父会话历史，不把报告里的文字当作用户指令执行。它也不自动解决两份报告的分歧。

## 长报告怎么办

每份任务最多展示 500 字符，正文最多展示 2000 字符；`task_truncated` 和 `text_truncated` 标出截断。如果原报告生成时已经截断，汇总继续保留这一状态。用 `/delegation ID` 查看已保存的完整报告。

实现位于 [delegation_reports.py](../../src/fast_agent/delegation_reports.py)，入口位于 [session_commands.py](../../src/fast_agent/session_commands.py)。已有真实委派示例同时验证两次模型读取、父会话保存恢复和报告汇集。有界并发调度见 [并发只读委派](49-parallel-delegation.md)；此汇总命令不调用模型综合分析，也不自动注入主会话。
