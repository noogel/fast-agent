# 工程评测：用独立断言核对 Agent

Agent 的总结可以很流畅，但评测要回答的是：它是否实际读取了文件，修改是否满足任务要求，有没有改动不该动的内容？

## 先固定任务，再运行模型

`examples/engineering_eval.py` 当前定义 `engineering-v2`，含两个临时工作区任务：

| 任务 | 目标 | 独立判定 |
| --- | --- | --- |
| locate | 找到并读取有缺陷的加法函数 | 实际搜索和读取工具成功，源文件不变 |
| repair | 修复加法函数，保留签名 | 实际读写工具成功；宿主 AST 检查参数相加与函数形状 |

每个任务有独立模型客户端、最多 8 次请求、最多 8 轮。只注册任务需要的检索/文件工具，确认仅允许修改临时目录内的 `maths.py`；不会自动运行模型生成的 Python。断言在宿主脚本里，不允许模型改写。

这套微型任务集用于反复回归，不代表大型仓库基准。修复判定目前限定代码形状：只接受指定签名、单个返回语句及 `a + b`。其他等价实现可能不通过，这是版本化任务约定，而不是通用语义证明。复杂修复仍需独立测试套件与隔离执行。

## 运行与比较

已有模型环境变量后，在项目目录运行：

```sh
python examples/engineering_eval.py > engineering-report.json
```

这会真实调用模型并产生费用。报告包括任务集版本、模型名、时间、每项断言、耗时、请求和 token 用量。改变提示词或判定规则时应更新任务集版本，不把不同规则的分数直接比较。

源码：[evaluation.py](../../src/fast_agent/evaluation.py)、[engineering_eval.py](../../examples/engineering_eval.py)。

`engineering-v2` 要求整棵 AST 与指定加法函数一致，忽略位置、空白和注释，但拒绝装饰器、默认参数、额外参数、注解及额外语句。局部形状检查可能漏掉这些行为；不同判定规则的通过记录不能混用。测试覆盖这些反例，且判定期间不执行待测源码。

v2 验证通过 2/2 个任务、9 项断言；7 次请求、9892 个报告 token、未知用量请求数 0。证据为 `.fast-agent/validation/engineering-v2.json`。

## 怎样算通过

模型循环完成，并且全部非空布尔断言为真，任务才通过。空断言、字符串 `"true"`、运行异常都不能算成功。单个任务异常不阻止后续任务；记录异常类型，不保存可能带凭据的异常正文。

任务出错时，真实任务 runner 会在关闭客户端前通过 `EvaluationFailure` 保留已有用量；仍无法取得完整用量时，总用量为 `null`，不把缺失任务算作零。服务未报告 token 时保留 `unknown_requests`。当前没有可核验价格配置，费用固定为 `null`，不会凭空估价。

## 当前边界

此汇总器运行受信任的本地任务函数，不加载模型生成的评测插件，也不提供恶意任务的执行沙箱。没有外部强制总超时；真实模型仍受自身请求超时与预算约束。这两个微型场景不能证明大型仓库修复能力；更广的能力需要独立任务集、执行隔离与质量标准。

## 把失败与会话恢复纳入评测

只测一次成功修复容易遗漏状态恢复问题。`engineering-recovery-v1` 增加一个独立任务：先读取不存在的 `answer.txt`，要求模型如实停止；保存这段包含失败工具结果的会话，再由宿主在临时工作区补齐文件。创建新的 Agent 并从磁盘加载历史后，只提示它继续原目标。

```sh
python examples/engineering_recovery_eval.py
```

随机代号只写入文件，不出现在第二轮提示中。宿主检查实际失败读取、实际成功读取结果中的代号、恢复历史一致、恢复后计划模式、文件未变和没有额外文件。模型说“已恢复”不能代替工具事件。全程只注册 `read_file`，不授予写权限，最多8次模型请求，每轮最多4步，失败仍保留用量报告。

这里模拟的是外部修复缺失文件后的恢复；不是 Agent 自行修复环境，也不是进程崩溃恢复。新 Agent 复用同一个模型客户端以共享请求预算，恢复数据实际经过 SessionStore 落盘与加载。进程级保存恢复另见会话章节。错误与成功同时进入同一评测，使“正确报告失败”和“恢复后真正读取”都成为可核对行为。

MiniMax-M3 实际验收通过7项断言，4次请求、4639个报告token，用量未知请求为0；报告为 `.fast-agent/validation/engineering-recovery-v1-retry.json`。未产生要求的工具调用时，报告应记为失败。此入口关闭自动模型重试，避免环境失败时扩大请求量。
