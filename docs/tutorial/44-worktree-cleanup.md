# 清理工作区，同时保留证据

归档只移动目录，不释放空间。任务交付后，可以先预览再显式清理已归档的工作区：

```text
/worktree-cleanup-preview 名称
/worktree-cleanup 名称
```

清理要求工作区归属和归档状态一致、没有活动或未知任务、没有未提交的跟踪文件变化，而且归档 HEAD 必须已经位于主仓库 HEAD 的祖先链。仅导出补丁不等于完成这个交付条件；独立提交仍会拒绝清理。

## 先保留什么

程序把除 `.git` 管理指针外的全部文件保存在私有证据包，包括未跟踪、忽略文件、二进制、权限和空目录。最多 8 MiB、4000 项，超限直接拒绝，不截断。链接、特殊文件和特殊权限也拒绝。每个文件都有校验值，包落盘后重新读取验证。

确认前必须停止外部编辑器和进程写入。内部任务锁并不能阻止所有外部程序。确认后再次采集对照，变化时拒绝清理；提交另存 Git 引用。随后才移除工作区。证据包继续占用空间，因此不保证总磁盘占用下降。

## 恢复与中断

返回的证据 ID 可用于 `/worktree-evidence ID`。恢复只写入全新的证据目录，不覆盖路径，不执行其中脚本；这是文件恢复，不会自动重新注册 Git worktree。

若删除中断，使用 `/worktree-cleanup-reconcile ID`。它核对证据、受保护提交、目录及 Git 注册，只更新状态，不重试删除。目录仍存在但内容变化、目录与注册不一致等情况需人工核实。

清理证据包与Git保护引用当前采用无自动到期策略，不提供删除这两类证据的命令；其他运行记录的隔离、恢复和到期清除见[存储回收](46-storage-retention.md)。源码入口：[worktree_cleanup.py](../../src/fast_agent/worktree_cleanup.py)、[worktree_snapshot.py](../../src/fast_agent/worktree_snapshot.py)。

## 验收证据

MiniMax指定场景验收21/21通过，覆盖临时工作区清理、证据保留和恢复；不会删除用户当前仓库来做验证。本地报告为`.fast-agent/validation/cleanup-real-retry.json`；报告来自临时夹具，不能推断任意服务、工作区或资源都已经验收。失败记录保留，模型口头结论不替代工具结果和磁盘断言。
